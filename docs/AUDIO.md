# 投屏音频：路由与验收

适用版本：0.4.0。技术栈：Agora macOS SDK 4.6.2、ScreenCaptureKit、AppKit / SwiftUI。

## 问题与证据

触发条件是开启投屏的「系统声音」，观众听到共享者的人声重复；关闭系统声音后正常。旧实现使用 Mixable 自定义音轨，SDK 定义此类音轨可与麦克风混音，因此重复发布是主要嫌疑。代码没有显式启动第二个麦克风采集器。

这是一项基于源码、SDK 定义和反馈现象的判断，尚未经真实双端 PCM 或听感确认。自动化检查关闭整个音频模块，仅测试配置和合成视频发布，不能宣称回声已经消失。

## 当前实现

| 声音 | 路径 | 控制 |
| --- | --- | --- |
| 我的麦克风 | Agora 原有语音连接 | 麦克风静音、采音音量；保持原有语音处理场景 |
| 共享电脑声音 | SCK → Direct 自定义轨 → 独立共享连接 | 发送暂停／恢复、发送音量 0–100 |
| 成员人声 | 语音连接的成员流 | 每个成员独立音量 0–400 |
| 正在观看的共享声音 | 仅订阅所选共享者的共享连接音频 | 独立收听音量 0–400 |
| 所有远端声音 | 本地播放 | 总音量 0–400、全部静音／恢复 |

- Direct 音轨禁本地监听和语音 DSP；共享连接明确不发布麦克风、自带屏幕音频或媒体播放器音频。默认语音连接不发布共享音频。没有通过全局关闭音频来实现 GUI 静音。
- SCK 排除本应用音频；macOS 15+ 显式关闭麦克风采集。它不会自动排除其他通话软件或浏览器中的声音。
- 共享音频取消默认自动订阅，只开启当前观看的 UID；切换、关闭和耳机静音时撤销旧订阅，入会和远端晚加入时重放设置。
- 音频面板可从语音房和投屏悬浮条打开，修改实时生效；观看窗还提供麦克风开关。成员语音和共享收听音量各自独立。
- 系统声音必须在开始共享整个屏幕时选择，之后可暂停／恢复；未选声音时需要重新发起共享才能启用。暂停同时阻止 PCM 推送和关闭音轨发布，保留人声与画面。
- 共享发送与收听音量在当前语音会话内保存，离房重置；既有语音音量偏好继续持久化。
- 窗口共享不支持声音，界面禁用并在底层拒绝，避免意外发送整个主屏的声音。

实现文件：`ShareAudioRouting.swift`、`ScreenShareSession.swift`、`SystemAudio.swift`、`ShareAudioControls.swift`。SDK 头文件 `AgoraEnumerates.h`、`AgoraObjects.h` 和 `AgoraRtcEngineKit*.h` 定义了 Direct／Mixable、音量范围和按连接订阅接口。

## 后续方案

首选进一步提供指定游戏／应用的声音选择，缩小系统声音的采集范围。这可参考 [OBS macOS 应用音频采集](https://obsproject.com/kb/macos-desktop-audio-capture-guide)，但需要处理应用退出、辅助进程、窗口画面与应用音频范围的差异。

输入／输出设备选择也可通过当前 Agora macOS SDK 的 `enumerateDevices` 和 `setDevice` 实现；应连同设备热插拔、丢失回退与偏好保存一起设计。[Discord 的设备与按成员音量设置](https://support.discord.com/hc/en-us/articles/360045138471-Discord-Voice-and-Video-Troubleshooting-Guide)可作为交互参考。

当前先保持 SCK 采集与 Agora 视频发布，避免在一次修复中同时替换全部媒体链路。统一 SDK 屏幕采集、虚拟声卡或独立发布进程都需单独验证。耳机与回声消除可降低扬声器串音，不能替代数字音轨去重。

[Apple 的应用音频排除定义](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration/excludescurrentprocessaudio)说明了当前排除范围；[SCK 音频与麦克风配置示例](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos)说明了两类音频可分别配置。

## 人工验收

按照 [测试规范](TESTING.md)，账号 A 使用原生端，账号 B 使用官方 Web；仅进入 A 自有且无其他人的测试频道。优先使用不同电脑和耳机，避免同机浏览器通话回放污染结果。

| 操作 | 应有结果 |
| --- | --- |
| A 正常说话，然后开启带系统声音的全屏共享 | 人声只有一份，游戏／播放器声音也可听 |
| A 闭麦／开麦 | 仅人声停止／恢复，应用声音和画面继续 |
| A 暂停／恢复系统声音 | 仅应用声音停止／恢复，人声和画面继续 |
| A 分别调整麦克风、共享发送音量 | 只改变对应声音，不互相影响 |
| A 调成员语音音量、全部静音／恢复 | 本地收听按设置变化，共享发送继续 |
| A 停止重开；B 关闭重开观看、晚加入 | 不遗留旧声音，不出现重复人声 |
| B 发布共享，A 分别调观看窗和成员音量 | 应用声音与 B 人声分别受控 |
| 展开悬浮音频面板，拖动滑条并切换到聊天 | 控件可点可滚动，滑条不会拖动整个面板，聊天和共享继续 |
| 切换到窗口共享 | 系统声音禁用，不录入其他应用声音 |

真实声音、设备切换与 UI 交互结果均由用户填写。出现重复时记录闭麦／暂停系统声音是否能消除问题、双方输入输出设备和测试时间即可；不要提交录音、会话或原始 SDK 日志。

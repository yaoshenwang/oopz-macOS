# 协议维护笔记

这是客户端维护所需的行为摘要。所有例子应使用合成标识，不包含真实响应、用户资料或认证材料。修改协议时记录证据来源：实际自有测试环境验证、官方公开实现参考，或尚待确认。

- REST 请求使用 OOPZ 请求头和应用运行时配置的 RSA 签名。规范串保留原始百分号编码查询参数，POST 拼接实际序列化 body。签名输入为规范串的 MD5 十六进制文本加毫秒时间戳，再使用 RSA-SHA256。
- HTTP 200 不代表业务成功。必须检查业务信封；共享状态上报还必须确认 data，不能把缺失值或 false 视为成功。
- WebSocket 使用二进制消息承载 JSON 信封，body 可能是 JSON 文本或对象。现行处理握手、心跳、消息、语音成员和共享状态事件。
- 查他人资料使用批量 personInfos；selfDetail 的 uid 查询参数不能用于获取他人资料。
- membersByChannels 返回成员对象集合，不是纯字符串数组；域昵称优先于全局昵称。
- 语音身份来自服务端的 userCommonId；共享使用独立鉴权与房间，不复用语音发布连接。
- 共享状态通过 OPEN / CLOSE 与快照共同确认，晚加入发现不能只依赖实时事件。
- 图片消息使用附件签名 URL；它可能过期，重新拉取消息后刷新。URL 不进入日志或公开测试样本。
